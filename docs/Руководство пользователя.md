# Руководство пользователя NaviXplore 1.0
Данное руководство содержит полную информацию по использованию фреймворка NaviXplore 1.0

## Системные требования
Данный фреймворк состоит из нескольких составляющих и, в зависимости от целей использования, имеет разные требования к системе, на которую будет установлен.
Для всех возможностей, включая запись набора данных из CARLA Simulator, обработку через алгоритм ORB-SLAM3 и использование векторной базы данных Qdrant с возможностью векторизации изображений, требуется система со следующими компонентами:
| Компонент               | Требование |
|-------------------------|------------|
| Процессор               | Уровня AMD Ryzen 9 5900HX |
| Видеокарта              | Не ниже NVIDIA RTX 3070 (рекомендуется от 16 гигабайт видеопамяти). Для использования векторизации изображений требуется именно видеокарта NVIDIA|
| Оперативная память      | От 32 ГБ     |
| Постоянная память (ПЗУ) | Около 500 ГБ |
| Операционная система    | Windows 11   |
| Дополнительно           | Установленный Git Bash|

Только для использования алгоритма ORB-SLAM3 с векторизацией изображений и сверкой с векторной базой данных Qdrant:
| Компонент               | Требование |
|-------------------------|------------|
| Процессор               | Уровня AMD Ryzen 9 5900HX |
| Видеокарта              | Любая видеокарта NVIDIA с 8 гигабайтами видеопамяти |
| Оперативная память      | От 16 ГБ |
| Постоянная память (ПЗУ) | Около 20 ГБ, не считая датасетов         |
| Операционная система    | Windows 11 / Linux |
| Дополнительно           | Установленный Git Bash. Инструкция по установке предназначена только для Windows, но, если CARLA Simulator не требуется, шаги будут незначительно отличаться. Изменится установка Docker, а также понадобится другое приложение для отрисовки содержимого контейнера с ORB-SLAM3 на хост-машине, так как здесь используется Windows приложение VcXsrv. Нужно учитывать, что при наполнении векторной базы данных пространство может быстро заполняться. Датасет на 10 минут может весить 1 ГБ |

Если записать записать датасет в векторную базу данных заранее, можно обойтись меньшими объёмами оперативной памяти и менее производительным процессором.
## Установка
Прежде всего, необходимо установить зависимости фреймворка.

- Для ORB-SLAM3 и векторной базы данных Qdrant понадобится Docker. Версию Desktop для Windows можно установить по ссылке: https://www.docker.com/products/docker-desktop/
- Для возможности отображать интерфейс ORB-SLAM3 на Windows, понадобится установить приложение VcXsrv. Оно доступно по ссылке: https://vcxsrv.com/
### Установка контейнера с ORB-SLAM3
- В терминале нужно ввести и выполнить при запущенном Docker Desktop:
```Shell
git clone https://github.com/jonasctrl/ORB-SLAM3-docker.git
cd ORB-SLAM3-docker
docker build -t orb_slam3:latest .
```
- Далее нужно запустить контейнер с ORB-SLAM3 первый раз:
```Shell
docker run -it --gpus all --env="DISPLAY" \
  --env="QT_X11_NO_MITSHM=1" \
  --volume="/tmp/.X11-unix:/tmp/.X11-unix:rw" \
  --name orb_slam3_container \
  orb_slam3:latest
  ```
- Чтобы к нему подключиться после запуска, можно ввести данную команду в терминал: 
```Shell
docker exec -it orb_slam3_container bash
```
- Чтобы проверить корректность установки, можно подключиться к контейнеру командой выше и скачать EuRoC датасет:
```Shell
cd /opt/orb_slam3

# создание директории для датасета
mkdir -p Datasets/EuRoc
cd Datasets/EuRoc/

# Скачивание датасета
wget -c http://robotics.ethz.ch/~asl-datasets/ijrr_euroc_mav_dataset/machine_hall/MH_01_easy/MH_01_easy.zip

# Создание поддиректории MH_01_easy и извлечение датасета в неё
mkdir MH01
unzip MH_01_easy.zip -d MH01/
```
- Чтобы при пересборке контейнера не пришлось заново скачивать большой файл с медленного сервера http://robotics.ethz.ch/~asl-datasets/ijrr_euroc_mav_dataset/machine_hall/MH_01_easy/MH_01_easy.zip, лучше его установить заранее на хост Windows, а после передавать внутрь контейнера командой:
```Shell
docker cp <путь_к_файлу_на_хосте> <имя_или_ID_контейнера>:<путь_внутри_контейнера>
```
- Установка пакетов для отображения окон контейнера на Windows (также запускать внутри контейнера):
```Shell
apt-get update && apt-get install -y x11-apps
```
- При каждом запуске/подключении к контейнеру необходимо прописывать команду:
```Shell
export DISPLAY=host.docker.internal:0
```
На Windows необходимо, чтобы при этом был запущен сервер VcXsrv через XLaunch.

- После можно проверить успешность конфигурации через команду ```xclock``` в контейнере. На Windows должны отобразиться часы.
- В VSCode в Windows можно установить дополнение Dev Containers от Microsoft для удобного подключения к запущенному контейнеру. После первого запуска контейнер удобно запускать через приложение Docker Desktop.
- Если понадобится получать внешние данные с камеры в контейнере с ORB-SLAM3, можно установить дополнительную библиотеку:
```Shell
sudo apt-get install libzmq3-dev
```

Для этой же цели также в контейнер по пути ORB_SLAM3/Examples/Monocular/ нужно скопировать файл из пути ORB-SLAM3-docker\orb-slam-3-extensions\camera.cc.
#### Запуск примера Monocular с помощью Python скрипта
- Внутри репозитория контейнера с ORB-SLAM3 (https://github.com/jonasctrl/ORB-SLAM3-docker) по пути ORB-SLAM3-docker/python-data-stream есть файл camera.py.
- Нужно установить зависимости через команды:
```Shell
  pip install opencv-python
  pip install pyzmq
```
- Проверка установки pyzmq:
```Shell
python -c "import zmq; print(zmq.zmq_version())"
```
- Далее сначала в контейнере нужно убедиться в правильной работе VcXsrv, после запустить пример командой:
```Shell
./Examples/Monocular/camera ./Vocabulary/ORBvoc.txt   ./Examples/Stereo/EuRoC.yaml   tcp://host.docker.internal:5555
```
По порту 5555 теперь ORB-SLAM3 будет ожидать изображения с камеры.
- Теперь можно с хоста Windows запускать скрипт для посылки изображений. Нужно убедиться, что камера включена, далее команда:
```Shell
python camera.py
```
## Установка симулятора городской среды CARLA Simulator
Репозиторий: https://github.com/carla-simulator/carla
Документация: https://carla-ue5.readthedocs.io/en/latest/tuto_first_steps/

- Чтобы иметь возможность установить нужный репозиторий с Unreal Engine, нужно связать свой зарегистрированный аккаунт GitHub с организацией Epic Games по инструкции: https://www.unrealengine.com/en-US/ue-on-github
- После успешной связки аккаунта GitHub с Epic Games можно открыть консоль Git bash в директории, в которую будут установлены репозитории Unreal Engine и CARLA Simulator, и ввести команду:
```Shell
git clone -b ue5-dev https://github.com/carla-simulator/carla.git CarlaUE5
```
- Далее открыть в той же директории терминал Windows PowerShell и запустить скрипт установки через:
```Shell
cd CarlaUE5
CarlaSetup.bat
```
- На моменте установки Visual Studio 2022 необходимо изменить компоненты:
![](images/Pasted%20image%2020250118165555.png)
- Должны быть проставлены следующие галочки:
![](images/Pasted%20image%2020250118165644.png)

В конце сборка в любом случае завершится ошибкой.
- Далее нужно собрать приложение CARLA с Python API через команду, введённую в терминале «Developer Command Prompt for VS 2022», находясь в директории репозитория CARLA
```Shell
cmake --build Build --target carla-python-api-install
```
- Далее и для каждого последующего запуска так же в консоли VS 2022:
```Shell
cmake --build Build --target launch
```
Для управления окружением и последующей передачи данных куда угодно, нужно сначала запускать Unreal Engine через команду выше, а после через Python использовать нужные команды.
## Установка репозитория
Данный репозиторий с программными решениями доступен по ссылке: https://github.com/stipot/NaviXplore.
Если он ещё не скачан, его можно просто клонировать в нужную директорию через команду:
```Shell
git clone https://github.com/stipot/NaviXplore.git
```

## Установка зависимостей Python
- Требуемая версия Python - 3.9.10.
- Чтобы установить библиотеки, нужно воспользоваться командой:
```Shell
pip install -r requirements.txt
```
PyTorch нужно устанавливать отдельно для версии CUDA используемой в системе видеокарты. Инструкция доступна по ссылке: https://pytorch.org/get-started/locally/.
## Установка векторной базы Qdrant
- Процесс установки описан в официальной документации: https://qdrant.tech/documentation/quickstart/
- Но здесь всё тоже продублировано. Сначала нужно запустить Docker, далее загрузить образ через команду:
```Shell
docker pull qdrant/qdrant
```
- Далее нужно установить Python-клиент (если он не установился через requirements.txt):
```Shell
pip install qdrant-client
```
- Запуск необходимо производить каждый раз из корня проекта NaviXplore 1.0 через:
```Shell
docker run -p 6333:6333 -v "$(pwd -W)/qdrant_data:/qdrant/storage" --name qdrant qdrant/qdrant
```
## Установка скрипта для обработки ORB-SLAM3
- По пути src/docker_ORB-SLAM3_part находится файл camera_carla_transfer_extended.cc. Его нужно скопировать внутрь контейнера с ORB-SLAM3 по пути ORB_SLAM3/Examples/Monocular/camera_carla_transfer_extended.cc. Это можно сделать командой:
```Shell
docker cp src/docker_ORB-SLAM3_part/Monocular/camera_carla_transfer_extended.cc orb_slam3_container:/opt/orb_slam3/ORB-SLAM3/Examples/Monocular/camera_carla_transfer_extended.cc
```
- Далее внутри контейнера (подключиться можно через VSCode) нужно открыть файл CMakeLists.txt и заменить содержимое на src/docker_ORB-SLAM3_part/CMakeLists.txt. Для удобства можно так же, как и для прошлого файла, переместить его командой:
```Shell
docker cp src/docker_ORB-SLAM3_part/Monocular/CMakeLists.txt orb_slam3_container:/opt/orb_slam3/ORB-SLAM3/CMakeLists.txt
```

- Ещё нужно установить библиотеку JSON в контейнер. Внутри него нужно запустить:
```Shell
wget https://raw.githubusercontent.com/nlohmann/json/v3.11.2/single_include/nlohmann/json.hpp -P ./include/nlohmann/
```

- В конце необходимо пересобрать ORB-SLAM3. Внутри контейнера нужно выполнить:
```Shell
./build.sh
```

## Использование фреймворка

- Основной файл для автоматического запуска всех команд называется auto_run.sh. Запускать его необходимо из пути src/Monocular/ Подсказку по его использовании можно вывести через:
```Shell
./auto_run.sh --help
```
- Также, доступен краткий аргумент:
```Shell
./auto_run.sh -h
```

- Также, скрипты можно запускать отдельно (тоже из пути src/Monocular/). Все аргументы остаются такими же, за исключением --rport, --rspeed, --tport и --tspeed. При их использовании нужно убрать первую букву (r или t). Справка тоже вызывается через --help, либо -h. При отдельном запуске скрипта ./test_monocular_dataset.py нужно также отдельно запускать ORB-SLAM3. Для этого внутри контейнера понадобится ввести (где carla_60.yaml - конфигурационный файл, генерируемый при сборе датасета):
```Shell
./Examples/Monocular/camera_carla_transfer_extended ./Vocabulary/ORBvoc.txt   ./Examples/Monocular/carla_60.yaml tcp://host.docker.internal:5555 tcp://host.docker.internal:5557
```

- Важно: сейчас после сбора данных через команду record конфигурационный файл автоматически в контейнер ORB-SLAM3 не переносится. Поэтому после каждого сбора датасета перед использованием нужно переносить .yaml файл из директории собранного датасета в контейнер по пути: /opt/orb_slam3/ORB-SLAM3/Examples/Monocular/.

- Пример запуска сбора датасета длительностью 5 секунд с сидом 12345:
```Shell
./auto_run.sh record --output ../../datasets/test/test_data_short_60 --duration 5 -s 12345
```

- Пример запуска отправки данных ORB-SLAM3 и приёма с записью отладочных данных, графиков, отчёта и всех обработанных данных:
```Shell
./auto_run.sh test --dataset ../../datasets/test/test_data_short_60 receive --data-port 5557 --debug --debug-output ../../datasets/test/debug_test_data_short_60 --collect-data --collection-data-output ../../datasets/test/collected_data_test_data_short_60 --collection-max-frames -1
```
